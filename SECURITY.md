# Security Policy

## Supported Versions

Security updates and patches are actively provided for the following releases:

| Version | Supported |
|---|---|
| `0.1.x` | Yes |
| `< 0.1.0` | No |

---

## Reporting a Vulnerability

The security and privacy of user credentials are the highest priorities for the Kinana project. If you discover a potential security vulnerability, we appreciate your help in responsibly disclosing it to us before public release.

### Reporting Procedure
Please **do not** open a public GitHub issue for security vulnerabilities.

Instead, please report security vulnerabilities using one of the following methods:
1. **GitHub Private Vulnerability Reporting**: Navigate to the [Security Advisories tab](https://github.com/A-ALOSIME/kinana/security/advisories/new) of the Kinana repository and click **Report a vulnerability**.
2. If private reporting is unavailable, reach out directly to the repository maintainer through their official GitHub profile channels.

### Information to Include
To help us triage and resolve the issue quickly, please include:
- A clear description of the vulnerability and its potential impact.
- Step-by-step instructions or a minimal proof of concept to reproduce the behavior.
- Operating system, architecture, and exact Kinana version tested.
- Any suggested mitigations or patches, if available.

### Response Timeline
- We will acknowledge receipt of your report within 48 hours.
- We will work diligently to investigate, confirm, and provide an appropriate patch.
- We kindly ask that you maintain responsible disclosure confidentiality until a security patch has been released.
